## 一、用户真正想得到什么

用户已经积累大量「量化技术分析」课程笔记，包括技术专题、股票日评、期货交易、读书课程、策略讲解及复盘。现在需要把分散内容组织成一套能理解、能检索、能复习的完整知识体系，并汇编成书。

读者应能从最终成果回答以下问题：

1. 课程讲了哪些核心概念，它们分别是什么意思、怎样识别、容易混淆什么？
2. 各种概念和指标怎样配合，分析行情时先看什么、后看什么？
3. 哪些属于市场观察信号，哪些属于局部交易方法，哪些已经形成明确的执行规则？
4. 某种方法适用什么市场、标的、方向、周期和行情，什么情况下应放弃？
5. 入场、确认、止损、止盈、仓位和加减仓分别依据什么条件？
6. 同一方法在不同课程中有何补充、修订、分歧或不同版本？
7. 成功案例、失败案例和未触发案例分别说明了什么？
8. 遇到实际问题时，能否快速查到有关规则、限制和原始出处？

“完整”指对实际可读取资料形成可追溯的知识覆盖。原资料没有定义、公式、参数或成交记录的地方，应明确登记缺口；不得靠补写常识制造完整性。

最终成果应同时具备：系统书稿、知识点库、方法与策略库、案例库、使用手册，以及便于其他 agent 审查的证据与覆盖记录。

### 2.3 来源使用规则

精简笔记用于发现主题与定位资料。进入正式知识点、策略卡和案例卡的关键断言，应回查对应完整稿；存在疑义且底层转录可定位时，再回查转录或字幕。

完整稿本身也可能有转录错误。核数报告属于已做过复核的线索，不能替代逐处证据。遇到已知原稿与成稿冲突时，应记录两者、检查修正依据，再决定采纳口径。

只有精简稿且找不到对应完整稿的内容，可以收录，但必须标记“仅精简稿可核”。来源不明的关键条件不得归入“规则完整”的策略。

本轮不要求联网补知识。确需补充当前市场制度或外部定义时，另列“外部补充”，引用官方来源及日期，并与原课程观点分清；不得让外部知识冒充课程原意。

## 四、先建立可追溯的资料底账

### 4.1 按文件建立来源身份

每份输入文件分配稳定的 `source_id`，例如 `SRC-000001`。编号只用于管理，不表示内容可信度或课程时间顺序。

`来源清单.tsv` 至少记录：

`source_id、相对路径、SHA256、文件类型、课号原写法、主题、版本标识、课程日期、日期依据、对应完整稿source_id、状态、备注`。

要求：

- 保留补零编号、同号不同文件、增强版和无课号专题。
- 建立“精简稿—完整稿—增强稿—转录”的关系。无法确认配对时标记待核。
- 日期优先来自正文明确日期或可定位原材料；不得用课号大小推定时间先后。
- 内容相同的备份可以组成重复来源组，但物理文件不能从底账消失。
- 初始清单冻结后新增的资料单独登记，避免处理总数无记录地变化。

### 4.2 为每份资料记录处理去向

每份资料必须落到以下状态之一：

- 已读并提取，关联具体知识点、方法、案例或证据。
- 已核实重复，指向代表来源及重复依据。
- 已读无相关交易内容，写明原因。
- 空稿或材料不足，写明缺少什么。
- 文件损坏、读取失败或来源关系待核，写明实际障碍。

重复文件只有在核实完全相同后才可免于逐份重读；近似重复仍需核对不同段落，尤其补充条件、例外、修订和价格。

不得只扫描标题、关键词或前几行，就标记“已读并提取”。长文件分段读取时记录进度，直到正文处理完毕。

### 4.3 抽取证据单元

每条可复用知识断言分配 `evidence_id`。`证据索引.tsv` 至少记录：

`evidence_id、source_id、行号或段落、原文短摘、主题对象、市场品种、周期、日期、观点主体、断言性质、核对状态、说明`。

断言性质至少区分：概念定义、观察条件、操作规则、假设例子、候选预案、自述已执行、复盘结果、统计结论、批评或反例。

证据要求：

- 行号对应已记录哈希的文件；同时给出小标题或原文短摘，方便定位。
- 一条证据保留理解条件所需的上下文，尤其否定词、前提和“可能、必须、只在”等限定。
- 不把长篇原文搬进证据表；原文短摘以足够定位为准。
- 自动抽取可用于找候选，最终写入书稿的关键条件需人工语义核对。

## 五、知识怎样组织

先形成“术语—概念—分析流程—方法—策略—案例—复盘”的关系，再组织章节。建议目录如下，可根据证据密度调整：

| 部分 | 主要内容 | 读者应获得的能力 |
| --- | --- | --- |
| 入门与全貌 | 课程体系、价格与概率、市场与周期、风险优先 | 知道分析和决策各环节的作用。 |
| 基础概念 | K线、量价、均线、趋势、常态、区间、缺口 | 能按明确条件识别基本状态。 |
| 指标与结构 | MACD、背离、乖离、布林、形态、时间窗口及课程专有指标 | 理解信号成立、失效和适用边界。 |
| 行情分析流程 | 环境、方向、结构、位置、多周期配合、候选筛选 | 能完成一套有顺序的分析。 |
| 交易方法与策略 | 突破、回测、趋势跟随、结构反转、日内等实际有据的方法 | 知道何时观察、确认、入场及放弃。 |
| 风险与执行 | 止损、止盈、仓位、加减仓、跳空、流动性、订单状态 | 能从规则中辨明具体动作及约束。 |
| 验证与复盘 | 交易记录、统计口径、胜率与盈亏比、回撤、失败复盘 | 能判断结论受到哪些证据支持。 |
| 股票与期货应用 | 市场差异、合约与周期、换月、过夜、做多做空 | 能辨明方法迁移的限制。 |
| 案例与查阅 | 成功、失败、未触发案例及问题索引 | 能从实际问题找到对应规则和原始证据。 |

课程专有缩写如 SFP、ELJ、MVB、MAVB、APL、LPA、LPK、E4K 等，只在资料实际涉及且可查证时收录。不要凭名称猜公式、英文全称或相互关系。

单一主题由一个核心知识点负责定义。其他章节引用其 ID 并补充应用条件，避免反复讲同一段基础定义。


### 6.5 使用手册与问题索引

另写一份便于快速查阅的手册，至少覆盖：

- 盘前：如何辨认环境、方向及候选标的。
- 入场前：怎样核对条件、止损和风险预算。
- 持仓中：哪些信号只是观察，哪些会触发具体动作。
- 平仓与复盘：如何核对执行、盈亏和规则失效。
- 暂不交易：什么情况下条件不完整或风险不可判断。
- 问题索引：如均线粘合、指标背离、跳空、止损后拉回、信号反复等，链接到相关概念与方法。

使用手册由已有规则构建。不同策略的互斥退出方式应分支呈现，不得凑成一条所有人通用的操作流程。

## 七、跨课综合、去重与冲突处理

### 7.1 可以怎样综合

- 多课对同一概念的重复解释，合并为一个规范定义，并保留来源。
- 一课给定义、另一课明确补充适用范围，可在核实对象相同后合并。
- 多课讲同一策略的连续修订，可以建立版本关系。
- 日评里的独立价格主要进入案例库；能抽象为通用规则的部分须有明确依据。

### 7.2 合成完整策略的限制

不能仅因几条规则看起来能配合，就把甲课入场、乙课止损、丙课仓位归为课程原有的一套策略。

跨课综合时必须逐项说明：属于同一方法的依据、市场与周期是否一致、条件是否兼容、哪些来自明确补充、哪些是编辑推演。

编辑者提出的组合可以单列为“待验证组合方案”，给出各模块出处和待验证问题，不进入“原课程完整策略”清单，不声称具有未验证的效果。

### 7.3 分歧的处理顺序

先检查分歧是否来自市场不同、周期不同、仓位不同、浮盈不同、收盘/盘中口径不同、书中观点与讲述者批评不同，或案例与通用规则不同。

若存在明确修订声明或足够上下文，记录旧版、新版和生效范围。仅因某课日期较新，不能自动认定它取代全部旧规则。

无法解释的冲突放入 `规则冲突与缺口.tsv`，记录双方证据及影响。书稿可以解释分歧，但不能偷偷选择更顺口的一边。

## 八、数字、术语和绩效的硬性核对规则

### 8.1 所有关键数字都要核对

重点包括行情价格、目标价、止损线、指标参数、均线周期、百分比、资金金额、合约手数、收益、胜率、回撤、日期和成交时间。

每个数字按以下顺序判断：

1. 原文件中有同义阿拉伯数字表达，允许千分位、单位等可证明的归一。
2. 原文件有完整中文口述或上下文唯一可还原的简称。
3. 可以由原文件给定数据正确计算或换算，须写出计算依据、单位与舍入方法。
4. 以上均不成立，删除具体数字或登记待核，不猜值。

去标点只用于发现候选；不能因此把两处不相干数字拼接成价格。尾数还原必须有本段明确的价区和对象；语境不足时保留尾数表述或去掉精确价。

跨课综合规则可引用多份资料，但每个历史价格必须绑定自己的来源、时点、品种与合约。不能把别课的价格借来填满本课案例。

`核数表.tsv` 至少记录：`目标文件、所在段落、数字原写法、含义、单位、来源证据ID、判定步骤、原文或算式、是否存在歧义`。

不设“每章至少几个点位”或“每卡至少几个数字”的指标。

### 8.2 必须逐处检查的高风险口径

- `50线`、`五日线`、`5MA`、`五小时线`分别保留原语义；不能未经证据把“50线”自动解释成五日线或50日线。
- 日线的5MA与60分钟图的5MA必须标清周期。
- 点数、价格百分比、账户风险比例、保证金使用率、杠杆比例不能混用。
- 日历日期与月内第几个交易日不同，时间窗口要注明口径。
- 股指名称、股票代码、期货品种、具体合约、主连图和换月前后价格须区分。
- 预期、条件满足、发出信号、发出委托、实际成交、持有、减仓、退出、止损分别记录。
- 作者自述已执行仍应标注其证据性质，不能升级为已核验成交记录。

### 8.3 绩效与验证结论

每项胜率、收益、盈亏比、回撤或策略效果声明，列明：样本来源、区间、市场、周期、交易次数或样本量、参数、费用与滑点口径、是否含杠杆，以及缺失项。

应区分：

- 原文观点或理论解释。
- 一个或多个课堂案例。
- 原文自述统计或回测截图。
- 数据、代码及执行假设可查的回测。
- 本轮确实重跑并获得一致结果的复现。

未重跑就不能写“本轮验证有效”。原稿提供了样本内结果，也不能自动称为样本外稳定。没有新检验数据时，交付待验证清单即可。

可另列未来验证需要检查的成本、未来数据泄漏、样本划分及参数敏感性问题；本轮不为得到漂亮结果搜索新参数。

## 十、执行阶段与完成条件

### 阶段 A：盘点与设计

读取相关说明、生成来源清单、识别文件配对和重复关系，建立初始术语表、章节目录与进度文件。

阶段完成标准：输入分母明确；异常文件有记录；输出目录和 ID 规则明确；每类资料都有处理路径。

### 阶段 B：制作可审查的样章

默认以“均线与趋势判断”为样章主题，结合来源充分的三加或趋势跟随方法，交付：一章正文、相关知识点卡、至少一个有证据的方法卡、可找到的案例、证据索引与分歧说明。

目的在于验证从证据到卡片、从卡片到书稿的链路。样章内不要强凑失败案例、参数或完整策略；素材没有就写缺口。

完成后做一次独立复核，修好模板再扩展。用户未要求等待审批时，报告样章位置后继续后续工作；不要因等不到样章反馈自行停工。

### 阶段 C：全量阅读与抽取

按主题和来源分批处理，每批建议 20—50 份独立正文，长篇按实际长度缩小批次。批次大小只用于管理，不决定内容取舍。

每批完成：阅读状态、证据索引、候选知识点和方法、数字疑点、来源去向，并更新进度。重复内容合并到已有卡片，保留新的条件和差异。

禁止只挑容易写的技术专题、只取标题含“策略”的文件，或大量跳过日评。日评中也可能首次出现规则、例外和修订。

### 阶段 D：全局综合与书稿

全量主题经过检索和抽取后，统一定义、消除无意义重复、建立版本关系，按知识依赖编写书稿和使用手册。

未获支持的推断不得在润色中变成确定规则。书稿中重要断言保留精简的证据标记，并链接到附录或证据索引。

### 阶段 E：独立复核与修正

完成下节规定的机械检查和语义复核。复核者发现错误，应定位到具体断言、原文与修改建议；主编修正后复验，保留记录。

### 阶段 F：最终交付

提供书稿、底层知识库、全部核对记录及交付书。声明完成时，必须把资料覆盖、规则完整度和效果证据分别说明。

## 十一、多 agent 协作与续跑

协作约束：

- 每次继续前先读进度，不重复整批覆盖已经审定的内容。

## 十三、验收标准

### 13.1 机械检查

- 冻结的全部输入文件均出现在来源清单中，处理去向无遗漏。
- 所有 ID 唯一，索引、卡片、章节和证据之间不存在悬空引用。
- 来源路径存在，定位信息与文件哈希对应。
- 每条关键规则有证据；没有证据的字段明确标为缺失、疑义或编辑推演。
- 核数表覆盖入场、止损、止盈、资金、比例、周期、日期时间和绩效等关键数字。
- 全书与分章同步，内部链接有效，无未处理的模板占位符、空标题、乱码或无理由重复。
- 输入文件结束时重新核对；若另一个任务期间有外部写入，登记变化并对受影响引用重查，不能笼统声称原文件未变。

机械检查可以写脚本。扫描结果只能用于发现问题，不得把正则命中当作事实成立或事实错误的最终判定。

### 13.2 语义复核

以下内容 100% 检查并记录结论：

- 标为“规则完整”的策略，其入场、确认、止损、退出和资金条件。
- 跨课合成规则的兼容性及版本关系。
- 关键入场价、止损价、目标价、仓位比例、指标参数及其单位。
- 绩效数据、统计结论和“有效”“失效”等效果判断。
- 时间周期、均线名称、否定条件、可选方案、预案与已执行状态。
- 存在原稿疑点、版本分歧、术语歧义的条目。

其他定义、叙述和辅助案例按主题与来源类型分层抽查，至少抽查 10%，且不少于 20 条；不足 20 条时全查。抽样分母、选样方式和样本 ID 必须记录。

抽查发现系统性错误时，扩大检查到受影响的同类记录，修正并复验后才通过。不要仅修正被抽中的一条。

`复核记录.tsv` 至少记录：`记录ID、审查对象ID、对应证据、检查类别、问题、修正、复核结论、复核者、时间`。

### 13.3 读者可用性

请另一个 agent 以未参与编写的读者视角，从书稿和手册回答以下问题，并实际点开出处：

如果资料确实不包含下列某类内容，例如规则完整的策略、失败案例或可确认的分歧，应核查覆盖记录和缺口说明，不强求补出实例。独立 agent 不可用时，采用第十一节规定的复核替代方案。

1. 找一个核心概念，能否说清定义、识别条件和一个不能成立的情形？
2. 找一个完整策略，能否按顺序找到环境、触发、止损、退出和风险约束？
3. 找一个不完整方法，能否立即看出缺什么，避免误当成完整执行规则？
4. 找两个看似矛盾的观点，能否知道差异来自周期、环境、版本还是未解决分歧？
5. 找一个失败案例，能否区分判断失败、正常止损、违规执行和资料不全？
6. 从一条数字或绩效结论出发，能否返回同一来源并核对？
7. 想查股票、期货、止损、背离等内容时，能否通过目录和索引找到？

答不出来的地方先修结构、证据或表述，再交付。

## 十四、覆盖、质量和最终汇报

覆盖报告分别报告以下数字，并写清分母：

1. 物理文件数量、不同来源数量、完全重复组和近似重复组。
2. 已读文件、经核实重复文件、无相关内容文件、空稿、读取失败与待核文件。
3. 已建立的术语、知识点、局部方法、完整策略、待验证组合方案及案例数量。
4. 有完整稿核对的断言数量、仅精简稿可核的断言数量。
5. 关键数字已核数、未决项、已解决分歧与未解决分歧数量。
6. 机械检查、全量高风险复核和分层抽查的结果。

数量用于说明覆盖情况，不作为要求 agent 凑概念、凑策略或凑字数的配额。

最终 `交付书.md` 应说明：完成范围、成果入口、资料清单与覆盖、章节结构、规则完整度、效果证据等级、发现并解决的错误、仍未解决的缺口及其影响、验收记录位置、后续最值得补充的资料。

出现空稿或不可消除的原稿歧义，只要已如实登记并且相关方法未被包装成确定规则，可以作为来源例外交付。可读取的有效资料尚未处理，或还有会改变交易动作的已知错写时，不得宣称全部完成。

本项目不设全书最低字数、固定章节长度、固定策略数量或每课最低数字数。篇幅服从知识与证据密度。

## 十五、禁止事项

- 编造源资料没有的概念定义、指标公式、价位、规则、成交或绩效。
- 用单个案例、课堂举例或作者自述，升级成经过独立验证的通用策略。
- 为了形成完整步骤，擅自补入仓位、止损、滑点、手续费或触发时点。
- 将被引用后批评的方法整理为课程讲述者认可的方法。
- 将时间较新的案例自动解释为对旧策略的全面推翻。
- 以课号去重后的数量宣称覆盖全部常规版和增强版。
- 用关键词摘要或固定模板重复改写，代替完整阅读与合并。
- 以行情事后结果倒推当时已经触发买卖条件。
- 在样章完成后自动结束整个项目，或未经用户反馈就写“用户已验收”。
- 用修改旧校验器、补无关数字、重复句子或凑字数达到表面通过。
