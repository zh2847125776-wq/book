## 二、🔴 T5 质检闸门是失败开放（fail-open）—— **已修复，见 §七**

### 2.1 自述的说法

> **故意注入异常卡**：质检闸门立即生效，`finished` 被置为 `false` 并拦截报错；
> **恢复正常状态**：质检通过（`qc_failed: 0`），`finished` 自动恢复为 `true`。

### 2.2 实测：它没测另一半

闸门代码（`reply/进度审计.py`）：

```python
qc = subprocess.run([sys.executable, '-X', 'utf8', str(BASE / '工具/质检_卡片充实度.py'), '--dir', str(dest)],
                    capture_output=True, text=True)
m = re.search(r'质检：(\d+) 个文件，(\d+) 个不通过', qc.stdout)
if m:                                          # ← 问题在这
    summary['qc_files'], summary['qc_failed'] = int(m.group(1)), int(m.group(2))
    if summary['qc_failed'] > 0:
        summary['finished'] = False
```

**质检工具跑不起来 / 输出对不上正则时，`m` 是 `None`，整个 `if` 被跳过，`finished` 保持 `True`。**

### 2.3 故障注入验证（我做的）

把质检路径指向不存在的工具，跑临时副本：

```
$ python 分片工作区/Codex/reply/_tmp_闸门测试.py
全分片核对通过，恢复记录已写入本分片out/07_审计与交付。

finished : True
qc_files : <缺失>
qc_failed: <缺失>
```

**结果**：审计照样宣布「全分片核对通过」，`finished: True`，**连 qc 字段都没写进去**。

> 这是**静默失败** —— 最坏的一种。质检工具哪天被改名、路径变了、或自己崩了，
> 审计会继续给出「通过」的绿灯，而内容问题无人过问。这正是 T5 本来要防的东西。

**测试后已清理**：临时脚本已删、两个输出文件已从备份恢复、真审计重跑确认状态还原（`finished: true` / `qc_files: 1131` / `qc_failed: 0`）。

### 2.4 建议改法（失败关闭）

```python
m = re.search(r'质检：(\d+) 个文件，(\d+) 个不通过', qc.stdout)
if not m or qc.returncode not in (0, 1):
    summary['qc_files'], summary['qc_failed'] = -1, -1
    summary['finished'] = False          # 跑不起来 = 不许通过
    summary['qc_error'] = (qc.stderr or qc.stdout or '')[-500:]
else:
    summary['qc_files'], summary['qc_failed'] = int(m.group(1)), int(m.group(2))
    if summary['qc_failed'] > 0:
        summary['finished'] = False
```

### 3.1 为什么会被改写

审计脚本有一条断言：


卡改了 → 回复（内嵌卡片）也变了 → 这条断言会炸。所以为了让审计继续通过，
`reply/*.md` 与 `strict.json` 里的 `reply_sha256` **都被同步更新了**。

### 3.2 后果

这条 guard 的本意是**抓「事后偷改回复」**。现在哈希链自洽了，

看不到这里发生过编辑。
