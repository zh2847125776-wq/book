参数：`<批号> <每组份数> <本轮最多组数，0=不限> <模型>`。驱动会在批内循环分组，一次调用跑完该批。

### 分段跑（正式推进方式）

```powershell
# 用批量循环，但每段结束后人工停掉，做段末质检
python -X utf8 工具/Antigravity批量循环.py 2 0 gemini-3.8-flash-high
```

批量循环会按「最早未完成批次」自动排：**批191 → 192 → … → 243 →（然后会进 276）**。

> ⛔ **跑到批243 完成立即停止。严禁让它滚进 批276–302** —— 那是 Codex 正在跑的活，
> 越界会造成跨片重复抽取。建议**每段约 10 批**（191–200、201–210、…、241–243），
> 段末手动停掉循环 → 跑段末质检 → 通过再起下一段。

> ⛔ **不要开 `工具/Antigravity看门狗.py`。** 它会自动重启循环，一路续跑越过 243 边界。

### 通道前置检查（这是最容易死的地方）


- **出口地区决定生死**：日本东京 / 机房 IP 会被拒

  驱动的网络抖动重试（4 次）会自己扛一部分；连续失败 3 组会熔断停机，那是要人工查通道，**不要硬重试**。

## 四、质量闸门（新增，**每组必跑**）

`严格官方入库` 的 guard 抓不到空心卡，所以本任务**增加一道质检**：

```powershell
python -X utf8 工具/质检_卡片充实度.py 07_审计与交付/Antigravity产出_SRC-xxxx_SRC-yyyy.md
python -X utf8 工具/质检_卡片充实度.py --dir 07_审计与交付        # 段末全量
```

| 级别 | 含义 | 处置 |
|---|---|---|
| **✗ 不通过** | 抽取规矩被抄进正文 / 关系段是空占位 / 案例段无内容 | **该组作废重做，不许放过** |
| △ 告警 | 来源头课号为空（外观）/ 同一组证据铺满 ≥3 个节 | 记录，不阻断 |
| ✓ 通过 | — | 继续 |

**三条硬规矩**（质检抓的就是这三条，写卡片时就要避开）：

1. **规矩是约束，不是素材。** `prompt` 里的抽取铁律（「仅记录≤300字完整原文字面」「不采信Vision推断」
   「禁截断铁律」…）**一个字都不许出现在卡片字段里**。
   「它解决什么问题」要写这条知识**解决什么交易问题**，不是复述抽取规则。
2. **禁止占位符。** `关联Sx与Cx；不跨源混用`、`见Sx与Cx` 这类句式一律视为未完成。
   - 「与其他概念的关系」必须写出**实际的概念关系**：对照 / 前提 / 互斥 / 补充（参考批362 的 K-32255：
     布林线 vs MACD、量能与 KDJ 的平行关系）。
   - 「案例与证据」必须有**具体标的、时间、数据**（参考 K-32255：上海机场回测、60%~75% 区间胜率）。
3. **逐节取证。** 不同小节挂各自支撑的证据号。若一整张卡每节都挂同一组证据号，说明没真正逐节回源。

**参考样本**：`07_审计与交付\Antigravity产出_SRC-011810.md`（K-32255 MACD精讲）——
这是本任务的质量基准线，写卡前先看一遍。

## 七、验收口径

每一组三条必须同时成立：

1. 驱动日志出现 **`✓ 入库成功`**，且入库输出满足
   **`证据 N | 验证通过 N | 未通过 无`**、**新卡数 == 回复卡数**；
2. **`质检_卡片充实度.py` 判定 ✓ 通过**（△ 可接受，✗ 不行）；
3. 主台账 `01_资料与索引\来源去向.tsv` 里对应 `source_id` 变为 **`已抽取`**。

**三者对上才算数。** 「脚本返回成功」不算，`guard: PASS` 单独也不算。

**完成标志**：批191–243 的 1,050 个 source_id 在主台账全部为 `已抽取`，
段末全量质检 ✗ 数为 0。
