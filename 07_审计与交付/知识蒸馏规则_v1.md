# 知识蒸馏规则 v1（阶段2：口述 → 可执行规则）

建立：2026-10-12 ｜ 状态：试点已验收，v2 提示词待复跑 ｜ 目标：把「老师口述的技术分析体系」变成**可回测、可编程、可接自动化交易**的规则库

---

## 0. 目标与边界

- **要什么**：从已建成的知识库（12053 张 K/S/C 卡 + 17825 条逐字证据）里，抽出**可被程序化执行**的交易规则，聚合成 1–3 个完整策略，最终能落地成自动化交易。
- **不要什么**：散文式"总结"、把模糊当明确、用模型自己的交易知识补参数、跨卡拼接出"看起来完整"的假策略。
- **红线**：任何规则必须能回到**单张卡 + 逐字证据**；参数缺失一律标 `null` + `ambiguity`，宁可留空，不许猜。

## 3. Stage B：建库、去重与 freq

### 表结构（`蒸馏/rules.db`）

```sql
CREATE TABLE runs(run_id TEXT PRIMARY KEY, model TEXT, prompt_version TEXT, n_rules INT,
                  n_unq INT, verbatim_pass INT, verbatim_fail INT, created_at TEXT);
CREATE TABLE rules(rule_id TEXT PRIMARY KEY, run_id TEXT, card_ref TEXT, source_ids TEXT,
                  evidence_ids TEXT, position TEXT, raw_quote TEXT, market TEXT, timeframe TEXT,
                  type TEXT, indicators TEXT, condition TEXT, execution_price TEXT,
                  ambiguity TEXT, stance TEXT, evidence_level TEXT, confidence TEXT,
                  cluster_id TEXT, freq INT, stance_weight REAL, created_at TEXT);
CREATE TABLE unquantifiable(id INTEGER PRIMARY KEY, run_id TEXT, card_ref TEXT, quote TEXT,
                  reason TEXT, stance TEXT);
CREATE TABLE params_to_optimize(param_id TEXT PRIMARY KEY, cluster_id TEXT, param_name TEXT,
                  why_unknown TEXT, source_refs TEXT);
```

### 去重与 freq 口径

1. **归一化**：统一指标别名（`20日线/二十日线/MA20/20均线` → `MA(20)`）、去掉空白与标点差异、统一百分号写法。
2. **聚类键**：`(market, type, 指标集合, condition 归一化模板)`；同键即同簇。
3. **freq = 簇内出现的不同 `source_ids` 数**（不是出现次数）——老师反复强调的才是核心体系，孤例大概率是噪音。
4. **立场权重**：讲述者采纳 1.0 ／ 未标注 0.8 ／ 书中作者观点 0.6 ／ 编辑者评注·被批评的方法 **不入库**。
5. 排序：`freq × stance_weight` 降序，人工复核前 30 簇。

## 4. Stage C：策略宪法（7 问模板）

每个策略必须逐项回答，答不出就写"待优化参数 + 需要什么证据才能定"：

1. **选池**：universe 怎么定（品种/指数/流动性/成分）
2. **入场**：精确布尔条件 + 成交价基准（次日开盘／信号K收盘／尾盘）
3. **加仓**：是否金字塔，条件与倍数
4. **止损**：固定百分比／ATR 倍数／结构位（前低、核心均线）
5. **止盈离场**：目标位／跟踪止损／指标反转
6. **仓位**：单笔风险比例、最大持仓数、最大总仓位
7. **过滤器**：大盘环境、波动率、流动性、时段（如避开开盘 15 分钟）

> 7 问里凡是原稿没给的，一律进《待优化参数清单》（`params_to_optimize`），**不自行填值**。这份清单就是接自动化交易前必须人工定死的参数表。

## 5. 试点验收记录（2026-10-12，10 张 S 卡）

**输入**：freq≥2 且证据最多的前 10 张 S 卡 + 其逐字证据（包 69 KB，见桌面 `蒸馏试点_10卡_20261012/`）
**产出**：20 条规则 + 64 条不可量化（共 84 条）
**独立校验**（`工具/蒸馏_校验产出.py`，回源底本 = 证据索引**全量原文**，不采信产出方自检）

| 校验项 | 结果 |
|---|---|
| 运行标记 | ✅ 存在，全文仅 1 个 JSON 块 |
| `rule_id` 格式 / `card_ref` 越界 | ✅ 0 异常 |
| **`raw_quote` 逐字回源** | ✅ **20/20 命中** |
| `unquantifiable.quote` 逐字回源 | ✅ 64/64（去掉 `【…】` 前缀后） |
| 立场过滤 | ✅ 20 条规则全为「课程讲述者采纳」，编辑者评注 0 条混入 |
| 卡片覆盖 | ✅ 10/10 有产出 |
| 置信度分布 | high 1 / medium 14 / low 5 |
| 类型分布 | filter 13 / exit 4 / entry_long 2 / risk 1 |

**结论：护栏有效——没有编造、逐字全中、立场没串。** 主要缺陷是"抽取过度保守"。

### 发现的问题与处置

| # | 问题 | 定性 | 处置（已写入 v2） |
|---|---|---|---|
| 1 | **6/10 张卡 0 条规则**（S-1854/S-0694/S-0858/S-1681/S-1694/S-1802 全进 unquantifiable） | **我的提示词 bug**：这些卡没有 `来源立场` 字段，模型按"只有讲述者采纳才可进 rules"整卡放弃 | v2 第 2 条：缺字段时 `stance=未标注`、**照常抽取**、confidence≤medium、ambiguity 注明 |
| 2 | `evidence_level` 被自创长描述填充（"卡面未标注（该卡无『底本层级』字段）"） | 规格没写"缺失时怎么填"；实测 2555 张 S 卡里只有 916 张带该字段 | v2 第 3 条：缺则一律填 `未标注` |
| 3 | `quote` 带 `【卡面文字】` 前缀，破坏朴素逐字校验 | 产出方自定约定（其自检脚本对该前缀有特判，故自洽但不标准） | v2 第 8 条：引用必须纯净，禁前缀；来自卡面正文时 `evidence_ids` 留空数组 |
| 4 | `condition` 出现 `0.005`，资料里只有"约0.5%" | **初判编造，复核后推翻**：0.5%→0.005 是忠实换算，且摘录原文逐字命中 | v2 第 7 条：允许换算但必须在 `ambiguity` 声明 |
| 5 | 5 条规则 `indicators` 为空数组 | 非缺陷（纯价格/百分比规则本无指标） | 无 |

### 已知局限

- freq 区分度低：2555 张 S 卡中 freq≥2 仅 76 张，其余 2477 张 freq=1 → **freq 只能当粗筛**，真正的权重还要靠 Stage B 的聚类结果。
- 证据索引里部分行的 `位置` 字段为空（如 E-636xx），`position` 允许空字符串。
- 本轮只跑 S 卡；K 卡（5869 张）与 C 卡（3533 张）是否入抽取范围待定（K 卡多为概念，C 卡多为案例）。
