## 二、⚠️ 核查方法上的关键坑（差点误判）

**第一轮核查得出「10,414 份未上传」——那是假阴性。**

仓库有 `.gitattributes`：

```
* text=auto eol=lf
```

而本地 `~/.gitconfig` 是 `core.autocrlf = true`。git 提交时把 **CRLF 转成 LF**，
字节一变，git blob SHA-1 就不同：

| 文件 | 原始 blob | LF 归一 blob |
|---|---|---|
| `(增强版)P1_3+详解.md` | `215e4735…` ✗ 不在仓库 | `484d5b58…` ✓ 在仓库 |
| `(增强版)P1_KDJ.md` | `ebf3e5e1…` ✗ 不在仓库 | `7ff6fcf8…` ✓ 在仓库 |

**必须同时算「原始」与「LF 归一」两个 blob，任一命中才算已上传。**
修正后：4,012 → **14,411**。

> 这个坑对后续任何核对都成立 —— 比对 GitHub 上的 Markdown 一律要先做行尾归一。
