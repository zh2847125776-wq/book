## 二、GitHub 上传可行性

### 硬约束

| 限制 | 阈值 | 本项目 |
|---|---|---|
| 单文件硬限 | **100 MB**，超出直接拒收 | ⚠️ **1 个文件超限**：`转写结果\量化技术分析20260811_重心下移_如果破5_反弹结束.wav`（**131.3 MB**） |
| 单文件告警 | 50 MB | 无（除上面那个） |
| 仓库建议上限 | **1 GB** | ⚠️ 主清单 749 MB ✓；转写清单 2.8 GB **超出** |

### 结论

**不能塞进一个仓库。** 建议拆两个：

| 仓库 | 内容 | 规模 | 可行性 |
|---|---|---|---|
| **A · 原件笔记** | `学习笔记\` + 三组 `_完整稿备份\` + `知识库\` + `_待汇编\` + 交付书/核数报告 | 14,426 份 / 749 MB | ✅ 在 1 GB 以内，直接推 |
| **B · 原件转写** | `转写结果\` | 10,226 份 / 2.8 GB | ⚠️ 超 1 GB 建议值（GitHub 会在 5 GB 才明显告警，实际可用）；**131 MB 的 .wav 必须先处理** |

**那个 131.3 MB 的 .wav 三个选项**（挑一个）：

1. **排除不上传** —— 它只是 1 份音频，`来源清单_转写.tsv` 里标的是「补充证据·按需回查」，
   不影响主清单的 14,426 份笔记。核对时工具会把它报为「缺失」，那是**预期内**的。
2. **用 Git LFS** —— `git lfs track "*.wav"`，GitHub 免费额度 1 GB 存储 / 1 GB 月流量，
   单放这一个文件够用。
3. **压缩后上传** —— wav 转 flac/opus 通常能压到 10 MB 以内，但要同步改清单里的哈希。

**转写清单进一步瘦身**（可选）：`.json` 占 2.42 GB 的绝大部分，是 ASR 原始输出。
如果只保留 `.srt`/`.txt`（250 MB），转写仓库能缩到 400 MB 以内。核对时按保留范围过滤清单即可。

## 四、怎么核对

### 工具

`工具/核对_GitHub原件.py`

```powershell
cd C:\Users\赵豪\dsh\交易知识体系汇编

# 全量（主 + 转写）
python -X utf8 工具\核对_GitHub原件.py <仓库克隆目录>

# 只核某一个
python -X utf8 工具\核对_GitHub原件.py <仓库克隆目录> --清单 主
python -X utf8 工具\核对_GitHub原件.py <仓库克隆目录> --清单 转写

# 抽查（快，先探通道）
python -X utf8 工具\核对_GitHub原件.py <仓库克隆目录> --sample 300
```

### 匹配策略（**文件名不唯一，所以不能只按文件名**）

1. **路径优先**：仓库里按「相对路径」能找到同名同结构的文件 → 直接比哈希（强证据）
2. **哈希兜底**：路径对不上时，看该 SHA256 是否出现在仓库里（容忍目录结构不同，弱证据）
3. 两者都没有 → 判「缺失」

### 输出怎么读

```
  清单条目 24652 ｜ 其中唯一哈希 21054 ｜ 仓库文件 24652 ｜ 仓库唯一哈希 21054

  ✓ 路径+哈希一致（强）      : 24652
  ○ 仅哈希命中（路径不同/内容重复，弱）: 0
  ✗ 哈希不符                  : 0
  ✗ 缺失（清单有、仓库没有）  : 0

  ★ 唯一哈希覆盖率: 100.00%（21054/21054）
```

**判据只有一条**：`✗ 哈希不符` 和 `✗ 缺失` 都为 0，且**唯一哈希覆盖率 100%**。
`○ 仅哈希命中` 不能单独当通过依据（重复内容会虚高）。

退出码：`0` 通过；`1` 有问题。

### 自校验记录

| 测试 | 结果 |
|---|---|
| 造 4 种情况（正常 / 路径不同 / 内容被改 / 缺失） | 四种全部正确识别 ✓ |
| 硬链接搭完整仓库，全量 24,652 份 | **24,652/24,652 路径+哈希一致，覆盖率 100%，20.6 秒** ✓ |

## 七、Arena 连接后的核对流程

```
① 原件按 §五 上传到 GitHub（两个仓库）
② Arena 连上 GitHub
③ 克隆到本地（或让 Arena 直接把仓库目录给我）
④ 跑：python -X utf8 工具\核对_GitHub原件.py <克隆目录>
⑤ 看报告：✗ 哈希不符 = 0、✗ 缺失 = 0、覆盖率 100% → 通过
⑥ 若有问题 → 工具给出 source_id + 相对路径明细，可直接定位到具体文件
```

**预期内的「缺失」**：若按 §二 排除了那个 131.3 MB 的 `.wav`，
报告会出现 **1 份缺失**，那是设计内的，不是问题。核对时先声明排除项即可。
